# 常见报错与排错

> 按"你看到的报错原文"找对应行。找不到就按顺序跑一遍文末的**五步定位法**。

## 一、装依赖阶段

| 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'app'` | 不在 `backend/` 目录下执行，或者没有激活虚拟环境 | `cd backend`，确认命令行有 `(.venv)`；脚本一律用 `python -m scripts.xxx` |
| `pip install` 卡在 `torch` 下载 / 几个 G | `sentence-transformers` 会拉带 CUDA 的 torch | 只装基础依赖即可：`pip install -r requirements.txt`（默认走云端 embedding，不需要 torch） |
| 装 `requirements-local.txt` 失败 | torch 版本与 Python 不匹配 | 单独装 CPU 版：`pip install torch --index-url https://download.pytorch.org/whl/cpu`，再装其余 |
| `error: Microsoft Visual C++ 14.0 is required`（Windows） | 编译型依赖缺 C++ 工具链 | 换预编译 wheel（pip 默认就是）→ 升级 pip：`python -m pip install -U pip` |
| `SyntaxError: ... unsupported operand type(s) for |` | Python 版本低于 3.10 | 升级到 3.11/3.12，重新建 venv |
| `Your system has an unsupported version of sqlite3. Chroma requires sqlite3 >= 3.35.0` | 老系统自带的 sqlite 太旧（常见于 CentOS 7） | 换 Python 3.11+ 的新环境；或在 Linux 上 `pip install pysqlite3-binary` 后按 Chroma 文档替换 |
| `ImportError: cannot import name 'HuggingFaceEmbeddings'` | 没装 `langchain-huggingface` | `pip install -r requirements-local.txt` |

## 二、模型接口阶段

| 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- |
| `openai.AuthenticationError: Error code: 401` | Key 错、过期、或复制时带了空格/引号 | 检查 `.env` 里 `LLM_API_KEY` 没有引号、没有多余空格；去后台确认 Key 还有效 |
| `Error code: 403 - ...` | 额度用完 / 模型未开通 / 地域限制 | 看平台后台的余额与模型权限 |
| `Error code: 404 - model not found` | 模型名写错（大小写、斜杠都要一致） | 用平台「模型广场」里的**完整 ID**，如 `Qwen/Qwen2.5-7B-Instruct` |
| `Error code: 400 - input must be a string`（向量化时） | LangChain 默认把文本转成 token 数组发送，兼容接口不认 | 本项目已在 `embedder.py` 里设 `check_embedding_ctx_length=False`；自己写代码时也要加 |
| `RateLimitError 429` | 免费额度限流 | 降低并发、加 `time.sleep`，或换付费档 |
| `APITimeoutError` | 网络慢 / 模型响应慢 | 调大 `LLM_TIMEOUT`；国内访问 OpenAI 需要代理 |
| 回答里全是 `\u5e74\u5047` 这种字符 | 前端把转义序列当普通文本渲染 | 后端 `json.dumps(..., ensure_ascii=False)`；前端 `JSON.parse` 后正常显示 |

## 三、向量库阶段

| 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Collection expecting embedding with dimension of 1024, got 768` | **换了 embedding 模型但没重建库** | `python -m scripts.ingest --rebuild`。换模型必须全量重建，manifest 里能看出当前用的是哪个 |
| `sqlite3.OperationalError: database is locked` | 多个进程同时写 Chroma（比如开了多个 uvicorn） | 只留一个后端进程；或用 `--workers 1` |
| `KeyError: 'documents'`（调删除接口时） | 文件名不匹配，接口返回了 404 | 中文文件名 URL 编码要对；先 `GET /api/documents` 拿准确名字 |
| 检索永远返回同一批结果 | 库里只有很少几个片段，或 `top_k` 大于片段数 | 看 `manifest.json` 的 `total_chunks`；加文档或减小 top_k |
| 上传成功了但搜不到 | 索引写入失败（向量化报错被吞掉） | 看后端日志；`GET /api/documents` 里该文件的 `chunks` 是否为 0 |
| 重建索引后结果反而变差 | 改了 `CHUNK_SIZE` 但旧片段没清干净 | 必须 `--rebuild`（不是默认的增量模式） |

## 四、前端 / 联调阶段

| 报错 / 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Failed to fetch` / `Network Error` | 后端没起、端口不对、或直接双击打开了 `index.html` | 确认 `http://127.0.0.1:8000/api/health` 能访问；前端必须用 `npm run dev` 或后端托管 |
| 浏览器控制台 `CORS policy ...` | 前端和后端不同源，且后端没放行 | 用 Vite 代理（本项目已配）；或在后端 `allow_origins` 加上你的域名 |
| `EventSource` 报 405 / 无法传参 | `EventSource` 只支持 GET | 改成 `fetch` + `ReadableStream`（本项目 `api.js` 的写法） |
| 回答"唰"一下全出来，没有打字机效果 | 有代理缓冲（nginx / 某些云网关） | 后端加 `X-Accel-Buffering: no`；nginx 配 `proxy_buffering off` |
| 一直显示"正在检索知识库…" | 首次请求在加载本地向量模型（可能几十秒）；或请求已失败但没报错 | 看后端日志有没有 `POST /api/chat 200`；本地模型首次加载慢属正常，第二次就快了 |
| `npm run dev` 报 `vite: command not found` | 没执行 `npm install` | 在 `frontend/` 目录执行 `npm install` |
| `You are using Node.js 16.x. Vite requires Node.js 18+` | Node 版本太低 | 升级 Node 到 20 LTS |
| 界面空白、console 里 `Uncaught SyntaxError` | 用了旧的 `dist` 构建产物 | 重新 `npm run build`，硬刷新浏览器（Ctrl+Shift+R） |
| 中文文件名上传后变成乱码 | 浏览器/系统编码问题 | 改成英文文件名，或确认 `Content-Disposition` 的 `filename*` |
| `curl` 报 `Invalid HTTP request received` / `400 Bad Request`，但浏览器里正常 | URL 里的中文没编码 | 用 `curl -G ... --data-urlencode "q=你的问题"`，别把中文直接拼进 URL |
| 首次启动卡在 `[index] 首次启动，正在为 N 个文档建库…` | 在下载向量模型 / 首次向量化，进度只在服务端日志里 | 等它跑完（示例 4 份文档约 1～2 分钟）；完成后会打印 `知识库就绪`。之后每次启动都是秒级 |

## 五、五步定位法（不知道错在哪时按这个顺序）

1. **依赖是否装对**：`python -c "import fastapi, langchain, chromadb; print('ok')"`
2. **配置是否读到**：`curl http://127.0.0.1:8000/api/health`，看 `llm_key_configured` 是不是 `true`、`embedding_model` 是不是你想要的
3. **库是否建好**：`GET /api/documents`，看 `total_chunks`；为 0 就 `python -m scripts.ingest --rebuild`
4. **检索对不对**：`GET /api/search?q=你的问题&k=4`。**这一步能区分"检索的锅"还是"生成的锅"**
5. **生成为什么不对**：`POST /api/chat/sync` 拿完整 JSON，看 `answer`、`sources`、`cited_ids`、`standalone_question`

经验：**80% 的问题出在第 3、4 步**——库里没东西，或者检索召回的根本不是那段。别一上来就怀疑模型。

## 六、Key 泄漏了怎么办

1. 立刻去平台后台**删除**该 Key（不是改密码，是删 Key）；
2. 生成新 Key，更新本地 `.env`；
3. 如果已经 push 到 GitHub：删掉仓库或强制改写历史（`git filter-repo`），**只删文件没用**，历史里还能翻出来；
4. 查账单，确认没有被盗刷。
